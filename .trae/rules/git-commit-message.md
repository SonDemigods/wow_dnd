### 核心原则
全中文环境：所有提交信息（Header、Body、Footer）必须使用中文，严禁出现英文单词或拼音。
语义清晰：提交信息应准确概括变更内容，避免使用“修改”、“更新”等模糊词汇。
原子提交：一个提交只做一件事，便于智能体进行代码审查和版本回滚。
### 提交信息格式
``` text
<类型>(<作用域>): <简短描述>

[可选] <详细正文>

[可选] <页脚>
```

### 类型定义
|类型|说明|智能体场景示例|
|--|--|--|
|feat|新增功能|新增天气查询技能、增加多轮对话记忆模块|
|fix|修复缺陷|修复意图识别误判、解决工具调用超时问题|
|docs|文档变更|更新技能使用说明、补充接口参数文档|
|style|代码格式|调整缩进、移除多余空行、统一命名规范|
|refactor|重构代码|优化提示词结构、重构工具链调用逻辑|
|perf|性能优化|降低首字响应延迟、减少无效上下文消耗|
|test|测试相关|新增意图识别测试用例、补充边界条件测试|
|chore|构建/工具|更新依赖版本、修改配置文件、调整流水线|
|revert|回滚提交|回滚上一个错误的技能发布版本|

### 作用域说明
全局：不指定作用域，如 feat: 新增全局黑名单过滤
模块：指定具体模块，如 fix(意图识别): 修复“帮我订机票”被误判为闲聊
工具：指定具体工具，如 feat(天气工具): 支持未来七天预报查询
配置：指定配置文件，如 chore(配置): 调整模型温度参数至0.7

### 正文与页脚
正文：当简短描述无法完整表达时，使用正文补充说明。每行不超过72个字符，段落间空一行。
页脚：用于关联任务或标注破坏性变更。
关联任务：关联任务: #1234
破坏性变更：破坏性变更: 天气接口返回格式已调整，需同步更新前端解析逻辑

### 注意事项
提交信息首字母无需大写，末尾不加标点。
类型与作用域之间无空格，作用域与简短描述之间有空格。
若变更涉及多个类型，拆分为多个提交。
智能体自动生成的提交信息需经人工审核后再提交。
