## P3-141：Tone.js 静态导入阻塞首屏

- **问题位置**：[src/main.ts:14](file:///d:/openSource/wow_dnd/src/main.ts#L14)、[src/modules/audio/service.ts:19](file:///d:/openSource/wow_dnd/src/modules/audio/service.ts#L19) 等 5 个文件 `import * as Tone`
- **修复策略**：
  1. `src/modules/audio/index.ts` 移除 `audioService` 静态导出，断开静态引用链
  2. `src/main.ts` 新增 `setupLazyAudioInit()`：监听 `pointerdown`/`keydown`（once），动态 `import('@/modules/audio/service')` 后 `audioService.init()`

- **风险**：低。音频非核心路径，`audioService.init()` 已具备 `initialized` 幂等保护。

## P3-146：stat_modifier/buff 被动技能完全失效

- **问题位置**：[src/modules/combat/composables/usePassiveSkills.ts](file:///d:/openSource/wow_dnd/src/modules/combat/composables/usePassiveSkills.ts)（`getStatModifiers()` 已定义但战斗管线从未调用）
- **问题背景**：`applyPassive` 对 5 种效果类型分发，但 `stat_modifier` 与 `buff` 仅记录日志完全不生效。逐职业统计可用被动：法师/猎人/牧师 0/3 可用，潜行者/术士/萨满/影刃猎手/龙脉术士仅 1/3 可用。`stat_modifier` 是出现频率最高的效果类型（39 个被动中约 18 个）。
- **修复策略**：三项接入
  1. **伤害管线接入 stat_modifier**（[pipeline.ts](file:///d:/openSource/wow_dnd/src/modules/combat/effects/pipeline.ts)）：`processDamagePipeline` 新增可选参数 `attackerStatModifiers`，在阶段 1 合并 `physical_attack_multiplier`/`magic_attack_multiplier`（影响 baseDamage）和 `bonus_physical_damage_percent`/`bonus_magic_damage_percent`（影响最终伤害）。新增 `extractAttackerModifiers` 辅助函数与 `StatModifierEntry` 类型，从 `effects/index.ts` 公开导出。
  2. **暴击判定接入 crit 加成**（[critCalc.ts](file:///d:/openSource/wow_dnd/src/modules/combat/composables/helpers/critCalc.ts)）：`rollPlayerCrit` 新增可选参数 `statModifiers`，叠加 `crit_chance`（0~1 小数转百分点）与 `crit_damage_multiplier`（暴击伤害倍率）。`Math.min(100, ...)` 防止暴击率超 100%。
  3. **buff 类被动写入 EffectContainer**（[usePassiveSkills.ts:applyBuff](file:///d:/openSource/wow_dnd/src/modules/combat/composables/usePassiveSkills.ts)）：根据 `effect.target` 决定写入容器：
     - `target='enemy'` + `stat='corruption_dot'` → 对当前攻击目标施加 `poison` effect（DOT，3 回合），`source: 'passive'`，调用 `effectRegistry.onApply` 与技能 buff 流程一致。
     - `target='self'` → 预留扩展点（暂无此类被动配置）。
  4. **调用方传参**：4 处 `processDamagePipeline` 调用与 4 处 `rollPlayerCrit` 调用均传入 `passive.getStatModifiers()`：
     - [usePlayerAction.ts](file:///d:/openSource/wow_dnd/src/modules/combat/composables/usePlayerAction.ts)（playerAttack）
     - [usePlayerSkill.ts](file:///d:/openSource/wow_dnd/src/modules/combat/composables/usePlayerSkill.ts)（AOE 分支 + single 分支）
     - [usePlayerItem.ts](file:///d:/openSource/wow_dnd/src/modules/combat/composables/usePlayerItem.ts)（伤害型物品）
  5. **onAttack 签名扩展**：`usePassiveSkills.onAttack(damage, targetEnemyId?)` 增加 targetId 参数，`store.ts` 在玩家攻击/技能命中后传入 `state.currentTarget.value?.id`，供 buff 类被动施加效果。
- **影响职业**：修复后法师（奥术精通 +10% 魔攻、法术致命 +5% 暴击）、猎人（精准 +8% 暴击、鹰眼 +5% 物理伤害）、潜行者（致命一击 +50% 暴击伤害）、术士（腐蚀术 DOT、恶魔契约 +12% 魔攻）、圣骑士（神圣审判 +8% 物攻）、萨满（元素精通 +10% 魔攻）、影刃猎手（伊利达雷决心 +20% 物攻低血）、龙脉术士（精华迸发 +12% 魔攻、龙息 +8% 魔法伤害）等职业的 stat_modifier 类被动全部生效。
- **测试**：
  - `tsc --noEmit` 通过
  - `vitest run` 178 文件 / 4502 测试全部通过
  - 同步更新 4 处 `store.test.ts` 断言（`passive.onAttack` 新增 targetId 参数）
  - 同步更新 `usePlayerAction.test.ts` / `usePlayerSkill.test.ts` / `usePlayerItem.test.ts` 中的 mock 工厂函数与调用签名
- **风险**：中。修复后法师/猎人/牧师强度会显著上升，需重测全职业 DPS 曲线（不在本批次范围）。
- **未接入项**（留作 P1 后续）：
  - `physical_defense_multiplier` / `magic_defense_multiplier`：需在阶段 0 之前合并到 `defenderCtx.baseStats`，涉及 baseStats 副本复制
  - `dodge_chance`：需在 `rollDodge` 调用前合并到玩家闪避率
  - `max_mana_multiplier` / `heal_bonus_multiplier` / `mana_regen_percent`：应在角色属性计算 / `receiveHeal` / 回合开始时单独处理，不属于战斗伤害管线

## P3-152：ESLint 边界规则仍为 warn

- **问题位置**：[eslint.config.js:15,20,51](file:///d:/openSource/wow_dnd/eslint.config.js#L15)
- **修复策略**：
  1. `sharedRules` 与 `strictModuleBoundaryRules` 的 `no-restricted-imports` 从 `warn` 升级为 `error`
  2. `@typescript-eslint/no-explicit-any` 从 `warn` 升级为 `error`（全项目无 `as any` 漏洞）
  3. 测试文件豁免：`test/**` 中 `no-restricted-imports: 'off'`、`@typescript-eslint/no-explicit-any: 'warn'`（mock 中 any 是合理用法）

- **效果**：IDE 阻断违规提交，模块边界强约束，防止底层模块反向依赖上层模块形成循环依赖。
