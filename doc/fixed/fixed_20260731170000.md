## 修复概述

为装备穿卸（equipItem/unequipItem）和商店购买（buyItem）的跨表写操作引入 `flushPersist` 等待机制，消除 fire-and-forget `persistInventory` 与回滚操作之间的竞态条件，确保 DB 状态与内存一致。

### 设计决策：使用 flushPersist 而非 db.transaction

原计划使用 `db.transaction('rw', [...], ...)` 包裹跨表写入，经调研发现三个工程障碍：

1. **persistCharacter 吞掉事务错误**：`character/store.ts` 的 `persistCharacter` 采用 fire-and-forget 模式（catch 后只上报不抛），事务内抛错会被 catch 捕获，导致外层 `db.transaction` 收不到错误信号无法触发回滚。
2. **withRetry 与外层事务冲突**：各 DB service 方法用 `dbService.withRetry` 包裹，外层事务失败回滚后 withRetry 重试时会抛 `TransactionInactiveError`。
3. **Vue 响应式状态与 DB 事务边界**：`spendGold`/`addItem` 先修改响应式状态再持久化，DB 事务回滚时内存状态不会自动回滚。

因此采用与 DB-1/DB-2（equipment 模块）一致的 `flushPersist` 策略：在回滚路径中等待 fire-and-forget 持久化完成，利用 Dexie 同表写入串行化特性（await 最后一个 persist 隐式 await 所有前序），确保回滚状态最终写入 DB。

## DB-1：unequipItem 跨表写无事务保护，可能产生物品复制

- **涉及文件**：[modules/equipment/store.ts](file:///d:/openSource/wow_dnd/src/modules/equipment/store.ts)（unequipItem 第 639-691 行）
- **问题表现**：`unequipItem` 中 `doUnequip` 通过 `inventoryAddItemCallback` 同步把装备放回背包（fire-and-forget `persistInventory1`），随后 `persist()` 持久化装备清空槽位。`persist` 失败时回滚（从背包移除已放回的装备），但回滚的 `removeItem` 也触发 fire-and-forget `persistInventory2`。若 `persistInventory1` 后完成，DB 中会保留装备（错误，应被回滚移除）。
- **修复方案**：
  1. 在 `unequipItem` 的 persist 失败回滚路径末尾，添加 `await inventoryFlushPersistCallback()` 等待回滚的 `persistInventory2` 完成。
  2. 利用 Dexie 同表写入串行化特性，`persistInventory1` 先于 `persistInventory2` 执行，await `persistInventory2` 隐式确保 `persistInventory1` 已完成，最终 DB 状态为回滚状态（无装备）。
- **关键代码**：
  ```typescript
  // DB-1/DB-2 增强：等待回滚的背包持久化完成，确保 DB 状态与内存一致
  if (inventoryFlushPersistCallback) {
    await inventoryFlushPersistCallback();
  }
  return null;
  ```

## DB-2：equipItem 跨表写无事务保护，可能产生物品丢失

- **涉及文件**：[modules/equipment/store.ts](file:///d:/openSource/wow_dnd/src/modules/equipment/store.ts)（equipItem 第 485-626 行）
- **问题表现**：`equipItem` 流程：从背包移除（`inventoryRemoveItemCallback` + fire-and-forget `persistInventory`）→ 卸下旧装备（`doUnequip` + `inventoryAddItemCallback` + fire-and-forget `persistInventory`）→ 装备穿上 → `persist()` 持久化装备。`persist` 失败时回滚（放回新装备到背包、移除旧装备、恢复旧装备），回滚操作也触发 fire-and-forget `persistInventory`，存在与原操作竞态。
- **修复方案**：
  1. 在 `equipItem` 的 persist 失败回滚路径末尾（前一次会话已实现），添加 `await inventoryFlushPersistCallback()` 等待所有回滚的 `persistInventory` 完成。
  2. 本次会话补充：在 `GameBootstrap.ts` 中注入 `flushPersist` 回调到 equipment 模块（前一次会话遗漏了 GameBootstrap 的注入）。
- **关键代码**（GameBootstrap.ts）：
  ```typescript
  // DB-1/DB-2 修复：同时注入 flushPersist，供装备 persist 失败回滚时等待背包持久化完成
  setInventoryCallbacks(inventoryStore.addItem, inventoryStore.removeItem, inventoryStore.flushPersist);
  ```

## DB-3：buyItem 跨模块多步写无 db.transaction 保护，回滚本身无事务

- **涉及文件**：[modules/shop/store.ts](file:///d:/openSource/wow_dnd/src/modules/shop/store.ts)（buyItem 第 360-532 行）
- **问题表现**：`buyItem` 涉及扣金币（`spendGold` → `persistCharacter`）、加背包（同步 `addItem` + fire-and-forget `persistInventory1`）、减库存（`shopDbService.saveSoldItems/saveShopItems`）。第 473-509 行 try-catch 实现了回滚（`removeItem` + `gainGold`），但回滚的 `removeItem` 触发 fire-and-forget `persistInventory2`，与 `persistInventory1` 竞态：若 `persistInventory1` 后完成，DB 中物品残留（错误，应被回滚移除）。
- **修复方案**：
  1. 在 `buyItem` 的库存更新失败回滚路径中，`removeItem` 之后添加 `await inventoryStore.flushPersist()` 等待回滚的 `persistInventory2` 完成。
  2. 利用 Dexie 同表写入串行化特性，确保 `persistInventory1` 先于 `persistInventory2` 执行，最终 DB 状态为回滚状态（无物品）。
  3. 保留现有 P2-54 手动回滚逻辑（removeItem + gainGold + errorReporter + toast），`flushPersist` 仅补充持久化竞态保护。
- **关键代码**：
  ```typescript
  // 回滚背包：移除已添加的物品
  try {
    inventoryStore.removeItem(itemId, quantity);
    // DB-3 修复：等待回滚的背包持久化完成，确保 DB 状态与内存一致
    await inventoryStore.flushPersist();
  } catch (rollbackErr) {
    console.error('[ShopStore] buyItem 回滚背包失败:', rollbackErr);
    errorReporter.report(rollbackErr, 'manual', { ... });
  }
  ```

## inventory/store.ts 改动

### flushPersist 函数（前一次会话已实现）

```typescript
async function flushPersist(): Promise<void> {
  if (pendingPersistPromise) {
    await pendingPersistPromise;
    pendingPersistPromise = null;
  }
}
```

### persistInventory 类型修复（本次会话）

修复 async IIFE 内 `currentCharacterId.value` 类型收窄失效问题（`Ref<string | null>` 在异步回调中无法保持 narrowing），提取局部变量 `charId`：

```typescript
async function persistInventory(): Promise<void> {
  const charId = currentCharacterId.value;
  if (charId) {
    const promise = (async () => {
      try {
        await inventoryDbService.saveInventory(charId, inventory.value);
        // ...
      } catch (err) { ... }
    })();
    pendingPersistPromise = promise;
    return promise;
  }
}
```
