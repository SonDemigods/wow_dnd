## 修复清单

### S1：CrossModuleQuery + ItemTemplateCache 直接 import `*/db` 问题

**问题**：服务层 2 个文件直接 import 其他模块的 db.ts，违反「跨模块依赖必须使用公共 index.ts 入口」硬约束。

**违规文件与修复**：

| 文件 | 修复前 | 修复后 |
|------|--------|--------|
| `src/services/CrossModuleQuery.ts` | `from '@/modules/map/db'` 等 4 处 | `from '@/modules/map'` 等 4 处 |
| `src/services/ItemTemplateCache.ts` | `from '@/modules/inventory/db'` | `from '@/modules/inventory'` |

**附带修复**：`src/modules/shop/index.ts` 原未导出 `shopDbService`，补充 `export { shopDbService } from './db';`。

**验证**：ESLint `no-restricted-imports` 规则在 src/ 中 0 违规。

---

### S4：引入 ESLint 模块边界强制规则

**问题**：项目无 ESLint 配置，跨模块 DbService 直接依赖违规只能靠人工 Code Review 发现。

**修复内容**：

1. **新增配置文件** `eslint.config.js`（ESLint 9.x flat config）：
   - `@typescript-eslint/no-explicit-any`: warn
   - `@typescript-eslint/no-unused-vars`: warn（argsIgnorePattern: `^_`）
   - `no-restricted-imports`: warn（禁止 `@/modules/*/db` 直接引用，allowTypeImports: true）
   - 测试文件豁免 `no-restricted-imports`（DB 层测试需直接 import db.ts）
   - Vue SFC 文件使用 `vue-eslint-parser` 包装 `@typescript-eslint/parser`

2. **新增依赖**（7 个 devDependencies）：
   - eslint@^9.0.0, @eslint/js@^9.0.0
   - @typescript-eslint/parser@^8.0.0, @typescript-eslint/eslint-plugin@^8.0.0
   - vue-eslint-parser@^10.4.1, eslint-plugin-vue@^10.9.2
   - globals@^17.7.0

3. **新增 scripts**：
   - `lint`: `eslint src test --ext .ts,.vue`
   - `lint:fix`: `eslint src test --ext .ts,.vue --fix`

**验证**：`npx eslint src --ext .ts,.vue` → 0 errors, 仅少量 warnings（no-explicit-any 和 no-unused-vars，均为既有代码）。

---

### S5：配置 vitest coverage 阈值

**问题**：vitest.config.ts 未配置 coverage 阈值，code_rule.md 规定的覆盖率标准无自动化强制。

**修复内容**：在 `vitest.config.ts` 新增 coverage 配置：

```typescript
coverage: {
  provider: 'v8',
  reporter: ['text', 'html', 'lcov'],
  thresholds: {
    statements: 85,
    branches: 80,
    functions: 85,
    lines: 85,
  },
}
```

阈值设为 85%（当前覆盖率约 90%，留 5% 缓冲），后续逐步提升至 90%。

## 评估暂缓项

### S2：引入 ICombatContext 降低 combat 扇出

**评估结论**：combat 模块有 22 处外部 Store 引用分布在 9 个文件中（store.ts + 7 个 composables + forms/store.ts），涉及 character/skill/quest/log/enemy/inventory 共 6 个外部模块。此重构需修改全部 9 个文件的函数签名和依赖注入方式，风险高、改动面大。

**建议**：作为专门的重构任务实施，按优化方案中 P1 阶段（3-5 周）规划执行。

### S3：引入 IBossContext 解耦 combat ↔ boss

**评估结论**：useBossMechanics 已不直接调用 useBossStore()（v1.0 改善），但 combat/store.ts 仍直接组合 useBossMechanics，boss/store.ts 被 combat store 直接调用。引入 IBossContext 需修改 useBossMechanics 接口和 combat/store.ts 实现。

**建议**：与 S2 一并规划实施。
