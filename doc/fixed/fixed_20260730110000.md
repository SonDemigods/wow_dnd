  - 修改：[src/modules/quest/store.ts](file:///d:/openSource/wow_dnd/src/modules/quest/store.ts#L65-L107)（新增 `GetInventoryItemCountCallback` / `AddItemToInventoryCallback` 类型与注入函数）

  - 修改：[src/services/GameBootstrap.ts](file:///d:/openSource/wow_dnd/src/services/GameBootstrap.ts#L71-L85)（注入双向回调）、第 157-159 行（dispose 清除回调）
  - 修改：[test/services/GameBootstrap.test.ts](file:///d:/openSource/wow_dnd/test/services/GameBootstrap.test.ts)（mock 适配 + 新增 2 个测试用例）
  - 修改：[test/quest/store.test.ts](file:///d:/openSource/wow_dnd/test/quest/store.test.ts)（beforeEach 注入回调 + afterEach 清除）
- **问题表现**：两个 Pinia store 运行时互相引用（inventory → quest 的 `onItemCollected`，quest → inventory 的 `addItem`/查询），构成明确循环依赖；且双方都直接 import 内部 store 路径，违反"跨模块依赖必须使用公共 index.ts 入口点"。
- **修复方案**：参考已有 `setInventoryCallbacks` / `setBossCreateFn` 回调注入模式：
  1. `inventory/store.ts` 新增 `setInventoryExternalCallbacks({ onItemCollected })`，`addItem` 内通过回调通知任务进度

  3. `GameBootstrap.initialize` 在 inventory 初始化后、equipment 初始化前注入双向回调
  4. `GameBootstrap.dispose` 清除双向回调引用，避免角色切换后回调指向旧 Store 实例
- **验证测试**：
  - `test/services/GameBootstrap.test.ts > initialize > 在 inventory 初始化后注入 inventory ↔ quest 双向回调（ARCH-2 修复）`
  - `test/services/GameBootstrap.test.ts > dispose > 清除 inventory ↔ quest 双向回调引用（ARCH-2 修复：避免回调泄漏）`

### TS-1. shop/store.ts tsc 编译错误修复

- **涉及文件**：[src/modules/shop/store.ts](file:///d:/openSource/wow_dnd/src/modules/shop/store.ts#L481) 第 481 行
- **问题表现**：`useToast().show({ type: 'error' })` 中 `'error'` 不在 Toast 支持的类型列表（`'info' | 'success' | 'warning' | 'danger'`）中，导致 `error TS2322: Type '"error"' is not assignable to type '"info" | "success" | "warning" | "danger"'`。项目记忆明确记录"tsc 仅预存 shop/store.ts 错误"。
- **修复方案**：将 `type: 'error'` 改为 `type: 'danger'`（语义对应"危险/错误"），与 useToast 类型定义一致。
- **验证测试**：`npx tsc --noEmit` 0 错误通过（历史遗留的最后一个 tsc 错误已消除，可考虑将 tsc 纳入 CI 门禁）

### QA-4. inventory/store.ts physical/magic_damage 物品效果空实现澄清

- **涉及文件**：
  - 修改：[src/modules/inventory/store.ts](file:///d:/openSource/wow_dnd/src/modules/inventory/store.ts#L409-L418)（方法文档注释）
  - 修改：[src/modules/inventory/store.ts](file:///d:/openSource/wow_dnd/src/modules/inventory/store.ts#L454-L457)（代码注释）
- **问题表现**：`useItem` 中 `physical_damage` / `magic_damage` 分支为空实现 TODO，原注释含糊（"TODO: 根据战斗系统设计实现"），易被误认为 bug。
- **经核实的设计结论**：此空实现是**正确的设计**，非 bug：
  - 伤害计算依赖战斗上下文（目标、暴击、BOSS 防御机制、荆棘反伤等）
  - 战斗系统的 `combat/composables/usePlayerAction.ts` 的 `playerUseItem`（第 680-757 行）已正确处理：先对目标造成伤害（processDamagePipeline + boss 防御机制 + takeDamage），再调用 `inventory.useItem` 仅消耗物品数量
  - inventory 模块不应依赖战斗上下文（会引入循环依赖且与职责分离原则冲突）
  - 非战斗上下文使用伤害型物品无意义（没有目标）
- **修复方案**：将含糊的 TODO 注释改为明确的设计说明文档：
  1. 方法头注释新增"伤害型物品设计说明"段落，解释为何不在本方法处理
  2. 代码内注释从 "TODO: 根据战斗系统设计实现" 改为 "伤害型物品由战斗系统处理（见 usePlayerAction.playerUseItem），此处仅消耗物品数量"
- **验证测试**：全量测试通过，无行为变化（仅注释和文档更新）
