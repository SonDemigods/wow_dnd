## P2 中等问题修复

### BIZ-10：宝箱事件未检查 addItem 返回值，背包满时物品静默丢失

| 项 | 内容 |
|----|------|
| 严重程度 | P2 |
| 位置 | src/modules/exploration/events.ts |
| 问题表现 | `treasure` 格子事件处理器中，`addItem` 未检查返回值，且日志在 `addItem` 之前记录。背包满时物品静默丢失，但日志显示"发现物品"，UI 与实际状态脱节。 |
| 修复内容 | ① 将日志记录和事件发射移到 `addItem` 之后；② 检查 `addItem` 返回值，若为 0（背包满）则走兜底奖励路径（`grantFallbackReward` 转换为金币+经验）；③ 扩展 `grantFallbackReward` 支持 `reason` 参数（`template_missing` / `inventory_full`），区分两种兜底场景的日志消息和 warn 行为。 |
| 新增测试 | `test/exploration/events.test.ts`：`BIZ-10：背包满时（addItem 返回 0）走兜底奖励，日志提示"背包已满"` |

## P3 低优先级问题修复

### BIZ-11：handleLoot 战斗日志使用 itemId 而非物品名称

| 项 | 内容 |
|----|------|
| 严重程度 | P3 |
| 位置 | src/modules/combat/composables/usePlayerAction.ts |
| 问题表现 | 战斗日志 `message` 使用 `${drop.itemId}`（内部 ID），而冒险日志正确使用了物品名称。 |
| 修复内容 | 将 `itemName` 定义移到 `addCombatLog` 之前，战斗日志使用 `${itemName}` 替代 `${drop.itemId}`；保留 `|| drop.itemId` 回退以处理空名称的防御性场景。 |

### BIZ-12：冒险日志无容量上限，存在无限增长风险

| 项 | 内容 |
|----|------|
| 严重程度 | P3 |
| 位置 | src/config/log.ts、src/modules/log/store.ts |
| 问题表现 | `logs` 数组无上限，长期游戏后内存与 IndexedDB 持续膨胀。 |
| 修复内容 | ① 在 `config/log.ts` 新增 `MAX_LOG_ENTRIES = 1000` 常量（50 条/页 × 20 页）；② `addLogEntry` 中新增日志后若超过上限则裁剪尾部最旧条目；③ `initialize` 加载历史数据时也做裁剪保护（处理上限保护引入前已超量的旧数据）。 |
| 新增测试 | `test/config/log.test.ts`：`MAX_LOG_ENTRIES 为正整数且不小于 PAGE_SIZE`；`test/log/store.test.ts`：`超过 MAX_LOG_ENTRIES 时裁剪尾部最旧日志`、`历史数据超过 MAX_LOG_ENTRIES 时加载后裁剪尾部` |
