## P1

### P13-001 普通怪物不掉落物品

- **文件：** src/modules/combat/store.ts
- **行号：** 约 L170-174
- **描述：** `endCombat('victory')` 中 `handleLoot` 仅对 `isBossCombat(e)` 的敌人调用，普通敌人永远不触发掉落逻辑。但 `config_mobs.ts` 中所有普通怪物均配置了 `drops`（DROPS_NORMAL / DROPS_HARD / DROPS_DANGEROUS），`useLootHandler.handleLoot` 的注释也写明"怪物与 Boss 均可配置 drops"。
- **影响：** 普通怪物击杀后无任何物品掉落，玩家只能从 Boss 获取装备/材料，严重影响游戏经济与进度。
- **修复：** 移除 `if (isBossCombat(e))` 条件，对所有敌人调用 `handleLoot`。同步移除未使用的 `isBossCombat` import。

## P2

### P13-002 onKill 资源钩子在 DOT 击杀时重复触发

- **文件：** src/modules/combat/composables/useInitiative.ts + src/modules/combat/store.ts
- **描述：** `tickAllEffects` 中 DOT 击杀敌人时调用 `sys.onKill?.()`，随后 `allEnemiesDead` 判定为 true 时调用 `endCombat('victory')`，后者再次对所有敌人调用 `sys.onKill?.()`。导致 DOT 击杀最后一个敌人时资源系统获得双倍击杀奖励。
- **修复：** 从 `endCombat('victory')` 中移除 `sys.onKill?.()` 和 `passive.onKill()` 调用，改为在各击杀路径（playerAttack/playerSkill/playerUseItem/tickAllEffects/singlePetTurn）中统一触发一次。同步在 `tickAllEffects` DOT 击杀路径补充 `passive?.onKill()` 调用（原仅有 `sys.onKill?.()`）。

### P13-003 onKill 钩子在直接击杀时不触发

- **文件：** src/modules/combat/composables/usePlayerAction.ts + usePlayerSkill.ts + usePlayerItem.ts
- **描述：** `playerAttack` / `playerSkill` / `playerUseItem` 击杀敌人时仅检查 `aliveEnemies.length === 0` → `endCombat('victory')`，但不调用 `sys.onKill?.()` 或 `passive.onKill()`。多敌战斗中玩家直接击杀一个敌人但其他敌人仍存活时，该击杀不触发资源获取和被动技能。
- **修复：** 在所有击杀路径中添加 `sys.onKill?.()` + `passive.onKill()` 调用：
  - `playerAttack`：`isDead` 为 true 且非 Boss 复活时触发
  - `playerSkill` 单体：同上
  - `playerSkill` AOE：每个 AOE 击杀（非 Boss 复活）触发
  - `playerUseItem`：同 playerAttack 模式
  - `singlePetTurn`：宠物击杀时触发

### P13-004 多选项事件弹窗关闭后事件格永久阻塞

- **文件：** src/composables/useGameActions.ts + src/modules/exploration/store.ts
- **描述：** `handleMultiOptionEventClose` 仅设置 `showMultiOptionEvent = false`，不清除 `pendingEventCell`。`revealGrid` 中 `if (cell.type === 'event' && cell.explored && !cell.completed && pendingEventCell.value) return false` 阻止了重新触发。
- **修复：** 在 exploration store 新增 `clearPendingEventCell()` 方法，在 `handleMultiOptionEventClose` 中调用。

### P13-007 useCamp 未校验当前格子类型

- **文件：** src/modules/exploration/store.ts
- **描述：** `useCamp()` 被调用时未校验玩家当前格子是否为 `rest` 类型。非营地格调用时 `campUsed` 被设为 `true` 但恢复效果未生效。
- **修复：** 在 `useCamp()` 开头校验 `currentCell.type !== 'rest'`，不满足则直接返回。

### P13-011 stopBgm() 不重置 currentBgmScene 导致 BGM 无法重启

- **文件：** src/modules/audio/synth/bgmSynth.ts
- **描述：** `stopBgm()` 清理 Pattern/Loop/振荡器/LFO/定时器，但不重置 `currentBgmScene`。`setBgmScene(scene)` 开头 `if (scene === this.currentBgmScene) return;` 导致相同场景后续调用被跳过。`EXPLORATION_END` → `stopBgm()` → `EXPLORATION_START` → `setBgmScene('exploration')` → early return → BGM 永不重启。
- **修复：** 在 `stopBgm()` 末尾添加 `this.currentBgmScene = null;`。

### P13-012 applyVolume() 在 stopBgm() 后误重启氛围振荡器

- **文件：** src/modules/audio/service.ts
- **描述：** `applyVolume()` 中检查 `getCurrentScene()`（非 null）且 `!isBgmOscRunning()`（true）时调用 `startBgmOscillator()`。但 `stopBgm()` 不重置 `currentBgmScene`（P13-011），导致用户调整音量时误重启振荡器。
- **修复：** 修复 P13-011 后此问题自动消失。

### P13-013 CombatPopup doSkip 缺 try/catch

- **文件：** src/components/popup/CombatPopup.vue
- **描述：** `doSkip()` 调用 `combatStore.skipTurn()` 时无 try/catch。若 `skipTurn()` 同步抛出异常，`isAnimating` 永远保持 `true`，玩家被永久锁定。
- **修复：** 用 try/catch 包裹 `combatStore.skipTurn()`，catch 中复位 `isAnimating` 并 toast 提示。

### P13-015 CombatPopup logsReversed computed 缓存失效

- **文件：** src/components/popup/CombatPopup.vue
- **描述：** `logsReversed` computed 使用 `logs.value === cachedLogs` 引用比较缓存。`addCombatLog` 使用 push（不替换数组引用），引用比较为 true 导致返回过期缓存，新日志不显示。
- **修复：** 移除手动缓存，直接 `return [...logs.value].reverse()`（日志 <100 条，开销可忽略）。
