## 概述

本次归档记录第二轮多代理交叉验证发现的 18 个问题的修复。涉及战斗逻辑（BOSS 复活、暴击/荆棘一致性、敌人先攻减速）、经济规则（商店商品映射、卖出价文档）、异常健壮性（NaN 防御、FileReader onerror、空数组除零）、资源清理（AudioService 节点 dispose）、数据校验扩展、文档对齐等维度。修复后 `current.md` 第二轮发现的问题已全部清零。

## 一、P1 严重修复（2 个）

### P1-1 伤害型物品击杀 BOSS 未触发复活机制【P1·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/combat/composables/usePlayerAction.ts`（playerUseItem 伤害分支） |
| 类型 | 战斗逻辑（BOSS 复活机制遗漏） |

**问题**：`playerUseItem` 中伤害型物品击杀敌人后，仅判断 `aliveEnemies.value.length === 0` 直接 `endCombat('victory')`，未调用 `checkBossRevive(target)`。且 `enemiesStore.takeDamage` 的返回值（isDead）未被接收。玩家用伤害型卷轴/物品击杀带 `canRevive` 标记的 BOSS 时，BOSS 应复活 50% HP，却被直接判定为胜利。

**修复方案**：
1. 新增 `let itemKilledEnemy = false;` 跟踪变量。
2. 将 `enemiesStore.takeDamage(...)` 改为接收返回值：`const isDead = ...; itemKilledEnemy = isDead;`。
3. 胜利判定处增加 BOSS 复活检查，与 `playerAttack`/`playerSkill` 一致：
   ```ts
   if (damageResult && aliveEnemies.value.length === 0) {
     const target = currentTarget.value;
     if (itemKilledEnemy && target && checkBossRevive(target)) {
       initiative.endPlayerTurn();
     } else {
       endCombat('victory');
     }
   }
   ```

## 二、P2 一般修复（5 个）

### P2-1 敌人先攻速度未应用 speed_down/freeze 减速效果【P2·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/combat/composables/useInitiative.ts`（buildInitiativeOrder） |
| 类型 | 战斗逻辑（先攻一致性） |

**问题**：`buildInitiativeOrder` 中玩家速度应用了效果修正 `effectRegistry.reduceSum(...)`，但敌人速度直接取 `e.stats?.dex ?? 5`，未读取 `enemyEffects` 中的 speed_down/freeze 修正。施加给敌人的减速效果不会改变其先攻顺序。

**修复方案**：对每个敌人构建 effectContext 并调用 `effectRegistry.reduceSum`，将修正值加到基础速度上：
```ts
import { createEmptyContainer } from '../effects';
// ...
for (const e of state.enemies.value) {
  const enemyCtx = log.createEnemyEffectContext(e);
  const enemySpeedMod = state.effectRegistry.reduceSum(
    state.enemyEffects.value[e.id] || createEmptyContainer(),
    'getSpeedMod',
    enemyCtx
  );
  const enemySpeed = (e.stats?.dex ?? 5) + enemySpeedMod;
  units.push({ id: e.id, speed: enemySpeed });
}
```

### P2-2 暴击与荆棘反伤计算基数不一致【P2·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/combat/composables/usePlayerAction.ts`（playerAttack 荆棘分支） |
| 类型 | 战斗逻辑（反伤基数一致性） |

**问题**：暴击在伤害管线之后应用（`finalDamage = pipeResult.finalDamage * critMultiplier`），但荆棘反伤 `pipeResult.thorns` 基于暴击前伤害，而 Boss 反击传入的是暴击后 `actualDamage`。两套反伤机制基数不一致。

**修复方案**：荆棘反伤也乘以暴击倍率，与 Boss 反击保持一致：
```ts
const thornsDamage = Math.floor(pipeResult.thorns * critMultiplier);
characterStore.takeDamage(thornsDamage);
```

### P2-3 importBackup 缺少 FileReader.onerror，Promise 可能永不 resolve【P2·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/data/service.ts`（ImportService.importBackup） |
| 类型 | 异常处理（Promise 悬挂） |

**问题**：`importBackup` 创建 FileReader 后仅设置 `reader.onload`，未设置 `reader.onerror`。文件读取失败时 Promise 既不 resolve 也不 reject，调用方永久挂起。

**修复方案**：在 `reader.readAsText(file)` 前补充 `reader.onerror` 回调，返回失败结果（与同文件 `validateBackup` 保持一致）。

### P2-4 handleLoot 随机掉落数量未校验 maxAmount < minAmount【P2·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/combat/composables/usePlayerAction.ts`（handleLoot） |
| 类型 | 边界防御（负数掉落） |

**问题**：`Math.floor(Math.random() * (drop.maxAmount - drop.minAmount + 1)) + drop.minAmount`，若 `maxAmount < minAmount`，amount 可能为负，破坏背包数据。

**修复方案**：加入边界校验：
```ts
const span = Math.max(0, drop.maxAmount - drop.minAmount);
const amount = Math.floor(Math.random() * (span + 1)) + drop.minAmount;
if (amount <= 0) return;
```

### P2-5 伤害管线 NaN 无防御传播，可腐蚀 HP 状态【P2·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/combat/effects/pipeline.ts`（processDamagePipeline） |
| 类型 | 异常处理（NaN 防御） |

**问题**：若效果系统返回 NaN（除零、未初始化字段），NaN 经管线传播至 `takeDamage`，使 HP 永久变 NaN 且无法自愈。

**修复方案**：在管线关键节点用 `Number.isFinite` 兜底：
```ts
const safeAttackerMod = Number.isFinite(attackerMod) ? attackerMod : 1;
const safeDefenderMod = Number.isFinite(defenderMod) ? defenderMod : 1;
const rawFinal = actualDamage - absorbed;
const finalDamage = Number.isFinite(rawFinal) ? Math.max(0, rawFinal) : 0;
```

### P3-9 AudioService.destroy 未 dispose 合成器与效果器节点【P3·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/audio/service.ts`（destroy） |
| 类型 | 资源清理（音频节点泄漏） |

**问题**：`destroy()` 清理了 BGM/timer/监听器，但未 dispose Tone.js 合成器与效果器节点（synths/reverbs/channels 等），HMR 热重载时泄漏 AudioNode。

**修复方案**：在 destroy 中遍历 dispose 所有节点：
```ts
const nodes: { dispose?: () => void }[] = [
  this.synth, this.membrane, this.fmSynth, this.noiseSynth, this.metalSynth,
  this.organVoice, this.masterFilter, this.masterVolume,
  this.sfxReverb, this.cathedralReverb, this.combatReverb, this.bgmReverb, this.bgmDelay,
  this.chorus, this.phaser, this.compressor,
  this.magicChannel, this.combatChannel, this.uiChannel, this.explorationChannel,
  this.characterChannel, this.standardChannel, this.bgmChannel,
  this.bgmOscGain, this.bgmFilter,
];
nodes.forEach(n => n.dispose?.());
this.bgmOsc?.dispose();
this.bgmFilterLfo?.dispose();
```

### P3-10 EventBus.emit 遍历期间监听器修改数组的快照保护【P3·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/bus/core.ts`（emit） |
| 类型 | 边界防御（遍历期间数组修改） |

**问题**：`emit` 用 `for...of this.listeners[event]` 遍历，监听器在执行中调用 `off`/`clearGroup` 会就地修改数组，导致跳过/重复回调。

**修复方案**：emit 时先快照再遍历：`const callbacks = this.listeners[event].slice();`。

### P3-11 singleEnemyTurn 移除死亡敌人后索引修正【P3·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/combat/composables/useInitiative.ts`（singleEnemyTurn） |
| 类型 | 逻辑修正（先攻公平性） |

**问题**：移除死亡敌人后 filter 仅当 `currentInitiativeIndex >= length` 时重置为 0，若被移除敌人位于当前索引之前，会跳过一个单位的回合。

**修复方案**：根据被移除元素相对当前索引的位置调整：`if (removedIndex < currentIndex) currentIndex--;`，再统一做越界兜底。
