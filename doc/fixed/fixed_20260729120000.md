### P0-1. 卸下装备时背包已满会导致装备永久丢失

- **涉及文件**：
  - [src/modules/equipment/store.ts](file:///d:/openSource/wow_dnd/src/modules/equipment/store.ts#L421-L444)（`doUnequip`）
  - [src/components/popup/CharacterInfoPopup.vue](file:///d:/openSource/wow_dnd/src/components/popup/CharacterInfoPopup.vue)（`unequipItem` 调用处）
- **问题表现**：`doUnequip` 中 `inventoryAddItemCallback` 的返回值（实际添加数量）被完全忽略。当背包已满（`INVENTORY_SIZE = 50`）且物品不可堆叠时，`addItem` 返回 0，但 `equipment.value[slot] = null` 已执行，装备被永久丢失。
- **修复方案**：
  1. 回调未注入时直接抛出错误，阻止卸下操作（替代原 `console.warn` 后继续执行的逻辑）。
  2. 检查 `inventoryAddItemCallback` 返回值，若 `added <= 0`（背包已满），回滚 `equipment.value[slot]` 并重新应用属性加成（`applyBonusForSlot`），然后抛出错误。
  3. UI 层（`CharacterInfoPopup.vue`）在 `unequipItem` 调用处添加 try/catch，捕获错误并通过 Toast 通知用户。
- **验证测试**：
  - `test/equipment/store.test.ts > Actions: unequipItem 回调缺失 > 未注入 addItem 回调时抛出错误并保留槽位（P0 修复：避免装备丢失）`
  - 全量测试 3906 项通过

### P0-2. equipment/db.ts 的 levelRequirement 使用 `|| null` 吞掉 0 值

- **涉及文件**：
  - [src/modules/equipment/db.ts](file:///d:/openSource/wow_dnd/src/modules/equipment/db.ts#L165)（`saveEquipmentTemplate`）
  - [src/modules/equipment/db.ts](file:///d:/openSource/wow_dnd/src/modules/equipment/db.ts#L70)（`mapTemplateToEquipmentItem`）
- **问题表现**：写入 `levelRequirement: item.levelRequirement || null`、读取 `levelRequirement: data.levelRequirement || undefined`。当 levelRequirement 为 0 时被吞掉，语义被改为"无等级限制"。inventory/db.ts 已修复为 `??`，但 equipment/db.ts 仍用 `||`，不一致。
- **修复方案**：改为 `?? null` 和 `?? undefined`，与 inventory/db.ts 保持一致，保留 0 值语义。
- **验证测试**：
  - `test/equipment/db.test.ts > levelRequirement=0 时存储为 null，读回为 undefined（用 || 而非 ??，0 被视为 falsy）` —— 测试用例已更新为验证修复后的行为

### P0-3. 管风琴音色双重增益应用导致音量失真

- **涉及文件**：[src/modules/audio/organVoice.ts](file:///d:/openSource/wow_dnd/src/modules/audio/organVoice.ts#L220-L238)（`triggerAttackRelease`）
- **问题表现**：构造合成器时通过 `volume: Tone.gainToDb(config.gain)` 设置音栓增益；`triggerAttackRelease` 又通过 `velocity * config.gain` 再次将增益乘到力度上。同一增益被施加两次（dB 音量 + 线性力度乘数），导致音栓增益被平方化（gain=0.5 实际衰减约 -12dB 而非 -6dB）。
- **修复方案**：移除 `triggerAttackRelease` 中的 `velocity * config.gain`，改为直接传递 `velocity`，仅通过构造时的 volume 参数控制音栓增益。与代码注释中"velocity 保持 0-1 线性值，synth 的音量已在构造时通过 volume 参数设置"的描述一致。
- **验证测试**：
  - `test/audio/organVoice.test.ts > velocity 直接作为最终力度（P0 修复：不再乘 config.gain，避免双重增益）`
  - `test/audio/organVoice.test.ts > 未传 velocity 时默认 0.7`

### P0-4. EventBus once() 回调抛异常时监听器永久泄漏

- **涉及文件**：[src/modules/bus/core.ts](file:///d:/openSource/wow_dnd/src/modules/bus/core.ts#L71-L84)（`once`）
- **问题表现**：`once` 方法中 `onceCallback` 内部 `callback(data)` 抛异常后，`this.off(event, onceCallback)` 永远不会执行。虽然 `emit` 用 try/catch 包裹不会崩溃，但一次性监听器永久残留，后续每次事件触发都会再次执行（违反"一次性"语义）。
- **修复方案**：使用 try/finally 确保注销：
  ```typescript
  const onceCallback = (data) => {
    try { callback(data); }
    finally { this.off(event, onceCallback); }
  };
  ```
- **验证测试**：
  - `test/bus/core.test.ts > once 回调抛错时监听器仍被正确移除（P0 修复：try/finally 保证注销）`
