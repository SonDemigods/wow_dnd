### BIZ-1：playerSkill 单目标分支缺少荆棘反伤处理

| 项 | 内容 |
|----|------|
| 严重程度 | P1 |
| 位置 | src/modules/combat/composables/usePlayerAction.ts |
| 修复内容 | 在 `playerSkill` 单目标伤害分支的 `applyBossCounterMechanics` 之后，补充荆棘反伤处理：`if (pipeResult.thorns > 0) { const thornsDamage = Math.floor(pipeResult.thorns * critMultiplier); ctx.character.takeDamage(thornsDamage); ... }`，与 `playerAttack` 保持一致。同时将 AOE 分支的荆棘反伤也改为乘以暴击倍率。 |

## P3 轻微问题修复

### BIZ-7：敌人技能治疗日志 skillName 使用 skillId

| 项 | 内容 |
|----|------|
| 严重程度 | P3 |
| 位置 | src/modules/combat/composables/useEnemyAction.ts |
| 修复内容 | 在 `case 'skill'` 的 `isHeal` 分支和 `case 'heal'` 分支中，添加技能名称查询：`const healSkillData = availableSkills.find(s => s.id === decision.skillId); const healSkillName = healSkillData?.name || decision.skillId;`，日志中使用 `healSkillName` 而非 `decision.skillId`。 |

### BIZ-8：buildItemPool 和 generateShopItems 使用不均匀的随机打乱算法

| 项 | 内容 |
|----|------|
| 严重程度 | P3 |
| 位置 | src/modules/exploration/service.ts, src/modules/shop/service.ts |
| 修复内容 | 将 `sort(() => Math.random() - 0.5)` 替换为 Fisher-Yates 洗牌算法：`const shuffled = [...items]; for (let i = shuffled.length - 1; i > 0; i--) { const j = Math.floor(Math.random() * (i + 1)); [shuffled[i], shuffled[j]] = [shuffled[j], shuffled[i]]; }`。 |

### BIZ-9：GAME_DATA_UPDATED 事件可能违反"数据变更不走 EventBus"原则

| 项 | 内容 |
|----|------|
| 严重程度 | P3 |
| 位置 | src/modules/data/service.ts |
| 修复内容 | 在两处 `GAME_DATA_UPDATED` 事件发射前添加注释，标注为"跨模块业务通知例外"（参考 code_rule.md §一.5），说明 data 模块不应反向依赖 baseStore，故通过 EventBus 传递最小信号通知重载。 |
