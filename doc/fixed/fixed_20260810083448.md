## 修复清单

### P1 严重（4 项）

#### P4-001｜护盾 handler 原地修改 effect.value，多段命中时护盾被重复消耗
- **文件**：`src/modules/combat/effects/handler.ts` — `reduceSum`
- **修复**：`reduceSum` 的 `getDamageAbsorb` 分支改为传递剩余伤害（remaining）而非原始伤害，每个护盾按剩余伤害计算吸收量并扣减，避免多护盾超额吸收。

#### P4-002｜Admin service 接受任意表名写操作，绕过 Store 业务校验
- **文件**：`src/modules/admin/service.ts`
- **修复**：新增 `WRITABLE_TABLES` 白名单（来自 `CONFIG_TABLES`）和 `assertWritable` 校验函数，在 add/update/delete/clear 方法入口调用，拒绝非配置表的写操作。读操作不受限。

#### P4-003｜allocateStat 未校验 MAX_STAT，属性已满时仍消耗点数
- **文件**：`src/modules/character/store.ts` — `allocateStat` Action
- **修复**：在 `allocateStat` 中增加 `if (character.value.allocatedStats[stat] >= MAX_STAT) return false;` 前置校验，导入 `MAX_STAT` 常量。

#### P4-004｜效果容器 replace 策略未调用旧 effect 的 onRemove 回调
- **文件**：`src/modules/combat/effects/container.ts`、`src/modules/combat/effects/pipeline.ts`
- **修复**：`addEffectToContainer` 新增可选 `registry` 参数，replace 和 maxStacks 刷新时调用旧 effect 的 `onRemove`；`removeEffectFromContainer` 改用 `splice` 原地移除替代 `filter` 重建数组，保持数组引用不变；`applyEffect` 传入 registry。
