## 已修复问题

### P3-137. 怪物 ID 重命名涉及配置/DB/引用全面更新

**问题背景**

怪物 ID 命名存在以下规范性缺陷：
1. 命名风格不统一：单字全小写（`gnoll`/`orc`/`lich`）与多字 snake_case（`iron_dwarf`/`dragon_whelp`）混用
2. 跨域 ID 冲突：`orc`/`undead`/`troll`/`dark_iron_dwarf` 既是怪物 ID 又是种族 ID（`RaceType` 联合类型）
3. 名称与 ID 不符：`demon`（Boss 名为"深渊卫士"）、`dragon`（普通怪名为"幼龙"）与 Boss `dragon_whelp`（名亦为"幼龙"）重名
4. 孤儿 ID：`gnoll_raider` 在 `src/`/`test/`/`doc/` 中均无引用
5. 兜底 ID 错误：`exploration/store.ts` 普通怪兜底为 `'goblin'`，该 ID 不存在于 `config_mobs`，触发兜底必崩

**修复策略**

采用"迁移基础设施先行 + 别名兼容层 + 分批重命名"三段式策略：

1. **阶段 0：迁移基础设施**
   - 新增 `alias-map.ts`：定义旧 ID → 新 ID 映射表，提供 `resolveEnemyId`/`isLegacyEnemyId` 函数
   - 新增 `migration.ts`：提供 `migrateExplorationGrid`/`migrateEnemyId`/`migrateEnemyIdArray` 迁移工具
   - 在 `enemy/store.createEnemy` 入口插入 `resolveEnemyId` 转换
   - 在 `GameBootstrap` Boss 创建回调入口插入 `resolveEnemyId`
   - 在 `exploration/store` 读取存档后调用 `migrateExplorationGrid`
   - 在 `quest/checkQuestProgress` 匹配前双向 `resolveEnemyId`
   - 修复兜底 ID：`'goblin'` → `monsterPool[0] ?? 'mob_gnoll'`

2. **阶段 1：冲突类 ID 重命名**（`orc`/`undead`/`troll`/`dark_iron_dwarf`）
   - 填充 alias-map 映射，修改 config_mobs/config_locations/config_quests 引用

3. **阶段 2：歧义类 ID 重命名**（`dragon`/`demon`/`spider`/`bandit`/`wolf`/`bear`）
   - `dragon` → `mob_young_dragon`（消除与 Boss `dragon_whelp` 名称重复）
   - `demon` → `boss_abyss_guard`（名称匹配）
   - 修改兜底 ID：`'dragon_whelp'` → `'boss_dragon_whelp'`

4. **阶段 3：规范化类 ID 重命名**（剩余 19 个普通怪 + 5 个 Boss）
   - 统一加 `mob_`/`boss_` 前缀
   - 删除孤儿 ID `gnoll_raider`
   - 兜底 ID 最终修复为 `'mob_gnoll'`/`'boss_dragon_whelp'`

5. **阶段 4：备份版本升级与文档收尾**
   - `BACKUP_CONFIG.backupVersion` 升级为 `'v1.1'`，`supportedVersions` 追加 `'v1.1'`
   - `importer.importData` 中新增 `migrateBackupEnemyIds` 函数，对备份数据中的旧怪物 ID 经 `resolveEnemyId` 转换后再入库
   - 修正 `enemy/types.ts` 注释中 `config_enemies` → `config_mobs`
   - 更新 `objective_utils.ts` JSDoc 示例 ID

**命名规范**

- 统一 snake_case
- 普通怪 `mob_` 前缀，Boss `boss_` 前缀
- 语义匹配名称，消除跨域冲突
