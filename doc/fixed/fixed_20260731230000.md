## 已修复问题

### P3-116. GameState 迁移到 Pinia Store — 大型重构

**问题背景**

原 GameState 散落在多个位置，没有统一 Pinia store 作为唯一数据源：
- `runtime_gameState` 表 `id='gameState'`：currentCharacterId、currentShopId、lastPlayedAt、settings（未使用）、initializedAt、maxLevel（未使用）
- `runtime_gameState` 表 `id='audio_settings'`：音频设置（masterVolume/sfxVolume/bgmVolume/muted/sfxEnabled/bgmEnabled）
- `character/db.ts`：封装 `getGameState`/`saveGameState` 读写 currentCharacterId
- `shop/db.ts`：直接调用 `saveGameState({ currentShopId })` / `getGameState()`
- `audio/db.ts`：使用独立键 `audio_settings` 存储音频设置

核心问题：
1. 无统一 Pinia store：GameState 散落在 IndexedDB 表 + 三个模块 store，没有单一数据源
2. 数据层越权：character/db.ts、shop/db.ts、audio/db.ts 直接访问 gameStateHelper，违反五层架构
3. 表语义不清：`runtime_gameState` 表用不同 `id` 承载多类数据
4. 未使用字段：`settings` 和 `maxLevel` 定义了但实际未被使用

**重构策略**

采用"收敛状态 + 保留模块 API（渐进式）"策略：
- `useGameStore` 持有全部全局状态，是唯一数据源
- character/shop/audio store 保留对外 API 不变，内部改为委托 GameStore（通过只读 computed 代理访问）
- 移除三个模块 db.ts 中的 GameState 操作，统一由 GameStore 持久化
- `audio_settings` 键数据迁移合并到 `gameState` 键的 `gameSettings` 字段
- `runtime_gameState` 表结构不变，备份/导入逻辑无需修改

**设计决策**

1. **只读 computed 代理（不提供 setter）**：characterStore/shopStore/audioStore 内的 currentCharacterId/currentShopId/settings 均为只读 computed，因为 computed setter 无法触发 async 持久化操作。所有修改必须显式调用 `gameStore.setXxx()`，确保状态变更与持久化原子完成。

2. **数据迁移幂等性**：`migrateAudioSettings()` 在已迁移过的 DB 上运行时，检测到 `gameState.gameSettings` 已存在则直接删除旧键，不重复迁移。测试用例覆盖此场景。

3. **保留模块 API 向后兼容**：characterStore/shopStore/audioStore 的对外 API（currentCharacterId / currentShopId / settings 仍可读写）保持不变，内部委托 GameStore。这降低了重构风险，调用方无需修改。

4. **runtime_gameState 表结构不变**：仅迁移 `audio_settings` 键的数据到 `gameState` 键的 `gameSettings` 字段，表结构不变，备份/导入逻辑无需修改。

5. **`toRawData` 剥离响应式**：持久化时使用 `toRawData(gameSettings.value)` 剥离 Vue reactive Proxy，避免 IndexedDB `DataCloneError`（fake-indexeddb 无法克隆 Proxy 对象）。

6. **fire-and-forget async 调用**：UI 事件中调用 audio store 的 async 方法采用 fire-and-forget 模式（`.catch` 错误处理），避免阻塞 UI 交互。

7. **GameStore 优先初始化**：App.vue 的 `onMounted` 中 GameStore 必须最先初始化（在 baseStore 之前），因为 characterStore/shopStore 依赖 currentCharacterId/currentShopId。

**风险点与应对**

- **只读 computed 赋值遗漏**：搜索 characterStore/shopStore/audioStore 内所有 `xxx.value =` 赋值语句，确保已全部替换为 `await gameStore.setXxx()`。如有遗漏会触发 Vue 警告且状态不生效。
- **audioStore async 方法签名变更**：`updateSettings`/`toggleMute`/`setMasterVolume`/`setSfxVolume`/`setBgmVolume` 从同步改为 async，调用方（`audio/service.ts`、`AudioSettingsPopup.vue`）需检查是否需要 await 或 fire-and-forget。
- **测试 setup 顺序**：GameStore 必须在 character/shop/audio store 测试之前初始化，否则读取为默认值。所有受影响测试的 `beforeEach` 需添加 `await useGameStore().initialize()` 或通过 `useGameStore().$patch()` 修改数据源。
- **shopStore init 逻辑变化**：原 `init()` 通过 `shopDbService.getCurrentShopId()` 从 DB 读取并赋值；改为只读 computed 后，currentShopId 已由 GameStore 持有，`init()` 仅需验证 savedShopId 有效性。
