## P3-172：combat ↔ character/talents 循环依赖（P1 高）

- **问题位置**：
  - `store.ts:38` 直接 `import { useTalentStore }`，仅用于读取 `effectSummary.unlockedPets`
  - `character/talents/store.ts:24` 反向 `import { usePetStore } from combat/pets`
- **问题表现**：违反 combatContext.ts 作为唯一外部 Store 引用点的架构契约，形成循环依赖
- **修复方案**：
  1. 正向依赖：`ICombatQuery.talent` 接口新增 `unlockedPets: string[]`，`combatContext.ts` 添加 getter；`store.ts` 删除 `useTalentStore` import，改用 `ctx.talent.unlockedPets`
  2. 反向依赖：`character/talents/store.ts` 删除 `usePetStore` import，新增 `onPetUnlock`/`onPetLock` 回调属性 + `setPetCallbacks()` 方法；`GameBootstrap.ts` Layer 3.5 注入回调
- **修改文件**：
  - `src/modules/combat/combatContext.ts`（接口 + 实现）
  - `src/modules/combat/store.ts`
  - `src/modules/character/talents/store.ts`
  - `src/services/GameBootstrap.ts`
- **测试更新**：`test/combat/store.test.ts`（log mock 添加 `resetSaveIndex`）

## P3-173：useBossMechanics 召唤小怪 IIFE 缺战斗状态守卫（P1 高）

- **问题位置**：`useBossMechanics.ts:195-255` `summon_minions` IIFE 中 `await bossCtx.createMinion()` 后无状态守卫
- **问题表现**：若战斗在 `createMinion` 期间结束，IIFE 仍会 push enemyId/enemyPositions 到已清理的状态
- **修复方案**：在 IIFE 内部 `await bossCtx.createMinion()` 后增加 `if (state.state.value !== 'fighting') return;` 守卫
- **修改文件**：`src/modules/combat/composables/useBossMechanics.ts`
- **测试更新**：`test/combat/useBossMechanics.test.ts`（makeStateMock 添加 `state: ref('fighting')`）

## P3-174：saveLogs 每次全量重保存，长战斗性能劣化（P1 高）

- **问题位置**：`useCombatLog.ts:58-59` 每次保存 `[...state.combatLogs.value]` 全量日志
- **问题表现**：50 回合 × 5 条/回合 = 250 条，每回合 3-5 次 saveLogs → 每次 250 次 put，O(n) 增长
- **修复方案**：
  1. 新增 `lastSavedIndex` 指针，每次仅保存 `combatLogs.value.slice(lastSavedIndex)` 增量日志
  2. `saveLogs(forceAll: boolean = false)` 参数，endCombat 时传 `true` 全量保存
  3. 新增 `resetSaveIndex()` 方法，startCombat 时重置指针
- **修改文件**：
  - `src/modules/combat/composables/useCombatLog.ts`
  - `src/modules/combat/store.ts`（startCombat 调用 resetSaveIndex、endCombat 调用 saveLogs(true)）
- **预期收益**：50 回合战斗末期每回合 put 次数从 750-1250 次降至 3-5 次

## P3-175：ResourceSystem as 穿透 + EnemyInstance 直接修改（P1 高）

- **问题位置**：
  - `store.ts:309` `(sys as unknown as { _maxValue: { value: number } })._maxValue.value += bonus`

- **问题表现**：类型系统无法捕获重命名/重构，违反"状态修改应通过 store action"原则
- **修复方案**：
  1. `BaseResourceSystem` 新增 `addMaxBonus(bonus: number)` 公共方法，`ResourceSystem` 接口同步新增
  2. `store.ts` 替换 `as unknown as` 为 `sys.addMaxBonus(bonus)`
  3. `enemy/store.ts` 新增 `setAiStrategy(enemyId, strategy)` 方法
  4. `ICombatCommand.enemy` 接口新增 `setAiStrategy`，`combatContext.ts` 实现代理
  5. `useInitiative.ts` 替换 `e.aiStrategy = ...` 为 `ctx.enemy.setAiStrategy(e.id, ...)`
- **修改文件**：
  - `src/modules/combat/resources/BaseResourceSystem.ts`
  - `src/modules/combat/resources/types.ts`
  - `src/modules/combat/store.ts`
