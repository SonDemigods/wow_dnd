## 修复清单

### TS-2：Boss 数据流类型断层：phases/intro 运行时附加属性未在类型中声明

**问题**：`GameBootstrap.ts` 第 79 行 `as EnemyInstance` 断言、`boss/service.ts` 第 106 行 `as EnemyInstance & { phases?: BossPhase[]; intro?: BossIntro }` 断言，靠两处断言桥接运行时附加属性。任何持有 `EnemyInstance` 的代码都无法静态获知 `phases`/`intro` 的存在。

**修复方案**：

1. **定义 `BossEnemyInstance` 接口**（[src/modules/boss/types.ts](file:///d:/openSource/wow_dnd/src/modules/boss/types.ts)）：
   - 新增 `BossEnemyInstance extends EnemyInstance`，包含 `isBoss: true`、`phases: BossPhase[]`、`intro?: BossIntro` 字段
   - 扁平化结构用于在 `enemyStore` / `enemiesData` 数组中传递，与普通敌人统一类型签名

2. **新增 `isBossEnemyInstance` 类型守卫**（[src/modules/boss/service.ts](file:///d:/openSource/wow_dnd/src/modules/boss/service.ts)）：
   - `function isBossEnemyInstance(enemy: EnemyInstance): enemy is BossEnemyInstance`
   - 判定依据 `enemy.isBoss === true`，由 `bossCreateFn` 构造不变量保证 `phases`/`intro` 存在
   - 用于 `useBossMechanics.initBossFeatures` 从 `EnemyInstance[]` 收窄为 `BossEnemyInstance`

3. **消除 `wrapAsBossInstance` 类型断言**（[src/modules/boss/service.ts](file:///d:/openSource/wow_dnd/src/modules/boss/service.ts)）：
   - 入参从 `enemy: EnemyInstance` 改为 `enemy: BossEnemyInstance`
   - 移除 `const bossEnemy = enemy as EnemyInstance & { phases?: BossPhase[]; intro?: BossIntro }` 断言
   - 直接读取 `enemy.phases` / `enemy.intro`

4. **消除 `GameBootstrap.ts` 类型断言**（[src/services/GameBootstrap.ts](file:///d:/openSource/wow_dnd/src/services/GameBootstrap.ts)）：
   - `setBossCreateFn` 回调返回类型显式声明为 `Promise<BossEnemyInstance | null>`
   - 移除 `as EnemyInstance` 断言，对象字面量结构满足 `BossEnemyInstance`
   - TypeScript 协变保证 `BossEnemyInstance | null` 可赋值给 `enemy/store.ts` 的 `BossCreateFn`（返回 `EnemyInstance | null`），无需 enemy 模块感知 boss 类型

5. **更新 `useBossMechanics.ts`**（[src/modules/combat/composables/useBossMechanics.ts](file:///d:/openSource/wow_dnd/src/modules/combat/composables/useBossMechanics.ts)）：
   - `initBossFeatures` 中将 `if (e.isBoss)` 改为 `if (isBossEnemyInstance(e))`
   - 类型守卫收窄后 `wrapAsBossInstance(e)` 接收 `BossEnemyInstance`，编译期类型安全

6. **更新 `boss/index.ts`**：导出 `BossEnemyInstance` 类型与 `isBossEnemyInstance` 函数

7. **更新测试文件**：
   - [test/boss/service.test.ts](file:///d:/openSource/wow_dnd/test/boss/service.test.ts)：`makeFlatBossEnemy` 返回 `BossEnemyInstance`，移除 `as EnemyInstance` 断言与 `as any` 属性访问
   - [test/boss/engine.test.ts](file:///d:/openSource/wow_dnd/test/boss/engine.test.ts)：`makeBoss` 返回 `BossEnemyInstance`，添加 `phases: []` 默认值
   - [test/combat/useBossMechanics.test.ts](file:///d:/openSource/wow_dnd/test/combat/useBossMechanics.test.ts)：`makeBossEnemy` 返回 `BossEnemyInstance`
   - [test/combat/composables/usePlayerItem.test.ts](file:///d:/openSource/wow_dnd/test/combat/composables/usePlayerItem.test.ts)：新增 `makeBossEnemy` helper，Boss 复活测试用 `BossEnemyInstance`

**设计要点**：

- **依赖方向保持**：`enemy/store.ts` 的 `BossCreateFn` 类型保持返回 `EnemyInstance | null`，不导入 boss 类型，避免 enemy → boss 反向依赖。`BossEnemyInstance extends EnemyInstance` 的协变保证 GameBootstrap 回调可赋值
- **扁平 vs 组合**：`BossEnemyInstance` 是扁平结构（extends `EnemyInstance`），用于数据传递；`BossInstance` 是组合结构（持有 `base` + `runtime`），用于战斗运行时。`wrapAsBossInstance` 负责从扁平重建组合
- **类型守卫位置**：`isBossEnemyInstance` 放在 `boss/service.ts` 而非 `types.ts`，遵循项目约定（类型守卫与逻辑函数同放 service 层，参考 `skill/service.ts` 的 `isValidTargetType`）

**验证结果**：
- `npx tsc --noEmit`：0 错误
- `npx vitest run`：175 文件 / 4471 测试通过
- `npx madge --circular src/`：无循环依赖
- Grep 验证：`src/` 下不再出现 `as EnemyInstance` 断言（仅注释中引用历史问题）
