## 一、资源清理修复（2 个）

### P3-1 `GameMain.vue` 升级动画 `setTimeout` 未清理【P3·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/components/GameMain.vue:354-356`（修复前） |
| 类型 | 资源管理（定时器泄漏） |

**问题**：`CHARACTER_LEVEL_UP` 事件回调中 `setTimeout(() => { levelUpTriggered.value = false; }, 1500)`，定时器 ID 未保存，`onUnmounted` 的 `gameBootstrap.dispose()` 不清理此定时器（dispose 仅清理 Store 监听器）。组件卸载后 1500ms 内定时器仍会执行，访问已卸载组件状态。

**修复方案**：
1. 新增 setup 作用域变量 `let levelUpTimerId: ReturnType<typeof setTimeout> | null = null`，供 `onMounted`/`onUnmounted` 闭包共享同一引用。
2. 将升级回调提取为命名函数 `onLevelUp`，内部保存定时器 ID 到 `levelUpTimerId`；回调开头清理上一次未触发的定时器，避免快速连续升级时定时器堆叠。
3. 在 `onUnmounted` 中：`eventBus.off(GameEvents.CHARACTER_LEVEL_UP, onLevelUp)` 移除事件监听（监听器与定时器紧耦合，移除监听是彻底防止泄漏的必要部分——否则卸载后监听器仍会触发并创建新的孤儿定时器），并 `clearTimeout(levelUpTimerId)` 清理未触发的定时器。

### P3-2 `ShopPopup.vue` 金币闪烁 `setTimeout` 未清理【P3·已修复】

| 项 | 内容 |

3. 在 `onUnmounted` 中 `clearTimeout(goldFlashTimerId)` 清理未触发的定时器（替换原占位注释 `// 保留，供未来扩展`）。

## 二、边界防御修复（1 个）

### P3-3 `animation/combat-effects.ts` `scaleDuration` 除零风险【P3·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/animation/combat-effects.ts:12-14`、`src/modules/combat/composables/useInitiative.ts:140` |
| 类型 | 边界防御（除零） |

**问题**：`scaleDuration` 中 `return Math.round(duration / speed)`，若 `speed` 为 0 会得到 `Infinity`；`useInitiative.ts:140` 的 `Math.round(500 / state.combatSpeed.value)` 同样依赖 `combatSpeed` 非零。`combatSpeed` 正常值为 1 或 2，为 0 概率极低，但缺乏防御性检查。

**修复方案**：
1. `combat-effects.ts` 新增常量 `const MIN_SPEED = 0.1`，`scaleDuration` 改为 `Math.round(duration / Math.max(MIN_SPEED, speed))`，确保除数至少为 0.1（speed 异常为 0/负值时动画变为极慢但可见，不产生 Infinity/负数）。
2. `useInitiative.ts` 敌人回合延迟同步改为 `Math.round(500 / Math.max(0.1, state.combatSpeed.value))`，内联 0.1 兜底（两处分属不同模块，未抽共享常量以避免跨模块依赖）。

## 四、可测性改进修复（1 个）

### P3-5 `enemy/service.ts` `calculateEnemyDamage` 随机性不可测【P3·已修复】

| 项 | 内容 |
|----|------|
| 位置 | `src/modules/enemy/service.ts:91-98`（修复前） |
| 类型 | 可测性（随机性注入） |

**问题**：`calculateEnemyDamage` 内部直接调用 `Math.random()` 计算伤害随机因子，未注入随机源。伤害计算的随机性在测试中只能通过 `vi.spyOn(Math, 'random')` mock 全局对象控制，存在副作用风险（若同批次其他代码调用 `Math.random` 会受影响），降低测试确定性与隔离性。

**修复方案**：
1. `calculateEnemyDamage` 新增可选第三参数 `randomFn: () => number = Math.random`，内部将 `Math.random()` 替换为 `randomFn()`。
2. **向后兼容**：默认值为 `Math.random`，生产环境所有现有调用无需改动，行为完全不变。
3. 在 `test/enemy/service.test.ts` 新增 `describe('calculateEnemyDamage 注入随机源（P3-5）')` 测试块（6 个用例），通过直接传 `() => 0` / `() => 1` / `() => 0.5` 注入确定性随机源，无需 mock 全局 `Math.random`，并验证防御减免、伤害下限、默认回退等场景。

**价值**：测试可直接注入确定性随机源，避免 mock 全局对象的副作用，提升测试隔离性与确定性；现有 `vi.spyOn(Math, 'random')` 测试因默认参数仍兼容通过。
